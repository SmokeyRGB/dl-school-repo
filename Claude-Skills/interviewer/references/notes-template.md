# Interview Notes Template

Use this structure for the closing summary and, if saved, for the output
file. Fill only what the interview actually surfaced — mark gaps explicitly
rather than inventing content.

```markdown
# Interview Notes — <topic / product idea>

Date: <date>
Elicitation objective: <one line, as confirmed at the start>

## Problem
- Core problem, in the interviewee's own words:
- Who is affected / who has this problem:
- When/where it shows up (trigger, scenario):
- Current workaround(s):

## Requirements signals
- Satisfiers (consciously stated wants):
- Dissatisfiers (surfaced via reaction/follow-up, not asked for directly):
- Delighters (unprompted, surfaced only through probing):

## Scope
- In scope for a first version:
- Explicitly out of scope:

## Success
- How the interviewee would recognize this is solved:
- Any metric or observable signal mentioned:

## Notable quotes
Verbatim or near-verbatim phrases worth preserving, especially any
emotionally loaded language that shaped follow-up questions:
- "..."

## Open threads / gaps
Anything raised but not fully explored, or anything the objective needed
that wasn't answered:
- ...

## Confirmed by interviewee
- [ ] Reviewed and confirmed accurate
```

If the user wants to continue into formal requirements docs, offer to hand
this file to the `requirement-writer` skill as the input for a Problem
Framing document.
